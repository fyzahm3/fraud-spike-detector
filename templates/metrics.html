What is knowable at authorization

The same dataset, restricted to what a payment rail can actually tell you. results/gateway_metrics.json

The full model draws most of its strength from an entity’s accumulated history — device graphs, email-cluster signal, rolling velocity. At the instant a payment is authorized none of that exists yet. A webhook carries an amount, a card network, a card type, an email domain and a timestamp.

So a second model was trained on the same real data and the same chronological split, restricted to exactly those {{ gw.n_features }} fields {{ h.help('gateway_model') }}. It is much weaker, and the gap is the measured cost of the history that has not accumulated yet.

Methodology, stated as constraints

Each of these is enforced by a test rather than by intention.

  • Threshold never sees test

    No function in the training code accepts the test frame. Hyperparameters and the decision threshold are chosen on validation and frozen. {{ h.help('threshold', '-method') }}

  • Features look only backwards

    Every graph and spike feature for a row is computed from strictly earlier rows, on half-open windows with deterministic tie-breaking. Verified against brute-force references and future-corruption tests. {{ h.help('leakage', '-method') }}

  • Same seed, same model

    Training is pinned to a fixed seed and thread count, so a rerun produces byte-identical models and scores.

  • The model writes no numbers

    Scores, confidence, costs, and recommendations are computed before the language model is called; it contributes the prose only. {{ h.help('llm_prose') }}

  • Decisions are append-only

    A resolution updates a status field and appends one row to the audit log. Nothing is edited or deleted; a correction is a new row. {{ h.help('audit_log', '-method') }}

The gap this does not close {{ h.help('dataset_gap') }}

The primary dataset is IEEE-CIS: real US card-not-present transactions. India's payment ecosystem is driven by UPI, IMPS/NEFT and wallets.

Adapting to UPI would mean replacing card-node features with directed address-to-address transfer edges, shortening rolling windows from hours to seconds, and adding device and geolocation telemetry. That work is described rather than claimed: no synthetic UPI data was generated, because fabricated data yields fabricated metrics.
